## Project Objective

10Web's AI chatbot handles thousands of customer support conversations per month across 93 languages — none of them labeled. The goal of this project is to figure out what users struggle with and which topics the bot handles worst, with no manual annotation.

To do that, 46,445 conversations are split into 169,709 topically coherent chunks, a custom embedder is trained via two-stage bootstrapped contrastive fine-tuning, and the chunks are clustered with UMAP + HDBSCAN into 24 cross-lingual intent clusters (Silhouette = 0.804, DBCV = 0.547, 12% noise). Chunk-weighted failure analysis pinpoints the three highest-risk clusters at 19.2%, 18.7%, and 18.0% headline failure rate. Daily Prophet forecasting beats naive persistence by 29% (wMAE = 10.71 chunks/day, MASE = 0.736).

## Steps to Reproduce Results

> **Note:** Everything — SQL, Python scripts, and notebooks — was developed and run on **Google Cloud Vertex AI Workbench** (Python 3.10, `europe-west1`), with BigQuery as the data backend. Reproducing results requires access to the BigQuery dataset `support-analytics-492410.support_analytics` (see `data/raw_data/DATA_ACCESS.md`) and GCP Application Default Credentials. If you don't have BigQuery access, `dashboard.html` and `paper/main.pdf` give you the full results without any setup.

All SQL runs in BigQuery (console, `bq` CLI, or Workbench terminal). All Python runs on Vertex AI Workbench or any environment with the conda env and GCP ADC.

### Step 1 — BigQuery data pipeline

```bash
bq query --use_legacy_sql=false < bq_pipeline/00_setup.sql
bq query --use_legacy_sql=false < bq_pipeline/01_copy_source_data.sql
bq query --use_legacy_sql=false < bq_pipeline/02_deidentify.sql
bq query --use_legacy_sql=false < bq_pipeline/03_prepare_docs.sql
bq query --use_legacy_sql=false < bq_pipeline/04_chunk_embeddings.sql
```

Optional Presidio NER pass:

```bash
python scripts/deidentify.py
```

### Step 2 — Semantic chunking and chunk clustering

The paper uses **two rounds** of bootstrapped contrastive fine-tuning. The commands below are a simplified summary; for the exact flags and parameters used to produce the paper results, see `reproduce.sh`.

```bash
python scripts/semantic_chunker.py
python scripts/chunk_clustering.py

# Round 1 fine-tuning + re-cluster
python scripts/contrastive_finetune.py --re-embed
python scripts/chunk_clustering.py --embed-suffix finetuned --skip-embed

# Round 2 fine-tuning (remove round-1 model first, then re-embed and re-cluster)
rm -rf data/models/finetuned_embedder
python scripts/contrastive_finetune.py --re-embed
python scripts/chunk_clustering.py --embed-suffix finetuned --skip-embed
```

### Step 3 — Post-clustering BigQuery tables

```bash
bq query --use_legacy_sql=false < bq_pipeline/05_failure_analysis.sql
bq query --use_legacy_sql=false < bq_pipeline/06_trends.sql
bq query --use_legacy_sql=false < bq_pipeline/07_chunk_evaluation.sql
```

### Step 4 — Run notebooks

Open JupyterLab and run the notebooks in order, or execute them from the command line:

```bash
jupyter nbconvert --to notebook --execute notebooks/01_baseline_clustering.ipynb
jupyter nbconvert --to notebook --execute notebooks/02_explore_clusters.ipynb
jupyter nbconvert --to notebook --execute notebooks/03_cluster_deep_dive.ipynb
jupyter nbconvert --to notebook --execute notebooks/04_failure_analysis.ipynb
jupyter nbconvert --to notebook --execute notebooks/05_trend_analysis.ipynb
jupyter nbconvert --to notebook --execute notebooks/06_evaluation.ipynb
jupyter nbconvert --to notebook --execute notebooks/07_forecasting.ipynb
```

### Step 5 — Compile the paper

```bash
cd paper && tectonic main.tex
```

## De-identification

De-identification happens entirely inside BigQuery before any Python code touches the data.

- **Structured columns:** SHA-256 pseudonymisation of `conversation_id`, `client_id`, and all name/email fields
- **Text pass A** (`02_deidentify.sql`): regex scrubbing for emails, URLs, IPs, phones, API keys, and OTP codes
- **Text pass B** (`scripts/deidentify.py`, optional): Microsoft Presidio NER pass for person, org, and location entities across all 93 languages
- **Validation:** `scripts/validate_deidentification.py` covers 15 synthetic test cases
